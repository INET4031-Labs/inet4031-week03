# Week 3: Container Orchestration with k3d

## Architecture Notice

This week requires your team container to support Docker's `--privileged` mode to run k3d (k3s in Docker). This enables nested Docker: a Docker daemon running inside your container, with k3d launching k3s nodes as containers within that daemon. **This has not been confirmed by the professor.** If your container does not support privileged mode, k3d cannot create cluster nodes and this lab cannot proceed as written.

Confirm with your instructor before starting this week.

## Sprint 2 Kickoff (Synchronous)

In this lab, you move the incident tracking application from Docker Compose into Kubernetes using a local k3d cluster. k3d creates k3s nodes as Docker containers inside your team container, giving you a full Kubernetes environment.

You will:
- Create a k3d cluster with control plane and agent nodes
- Use kompose to translate your Docker Compose file into Kubernetes manifests
- Identify and fix two critical security problems in kompose output (plaintext credentials and Recreate deployment strategy)
- Deploy the application into the cluster
- Extend the Ansible playbook to include k3d cluster setup

## Learning Objectives

- Create a k3d cluster inside Docker-in-Docker and obtain a working kubeconfig
- Translate a Docker Compose file to Kubernetes manifests using kompose
- Identify and fix insecure defaults in generated manifest output
- Deploy a three-tier application to Kubernetes and verify all pods are healthy
- Extend the Ansible playbook with a k3d cluster setup role

## Prerequisites

- Week 2 complete: Docker Compose stack is running inside your team container
- Docker daemon is running inside the team container (nested Docker)
- kubectl and k3d are available or installable inside the team container
